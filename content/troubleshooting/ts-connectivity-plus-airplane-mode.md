# 비행기 모드에서 앱이 안 열렸다

출시 전 점검에서 비행기 모드를 켜고 앱을 실행해봤다. 로컬 우선으로 설계했으니 당연히 열릴 줄 알았는데 안 열렸다.

## 환경

- Flutter / Dart
- connectivity_plus
- Supabase (원격 DB, Edge Function)
- 로컬 SQLite

## 문제 상황

1. 비행기 모드로 앱을 켜면 "시작을 완료하지 못했어요"가 뜨고 앱을 아예 못 쓴다
2. 오프라인이 한 번 감지되면 네트워크가 돌아와도 계속 막힌다
3. 다시 시도를 눌러도 아무 변화가 없다

로컬 DB에 데이터가 다 있는데도 진입이 막혔다. 로컬 우선으로 설계한 의미가 없는 상태였다.

## 원인

### 원격 조회가 앱 시작 조건에 들어가 있었다

AI 사용량 조회를 앱 시작 성립 조건에 넣어뒀다. 오프라인이면 이 값을 못 읽고, 못 읽으면 시작이 실패한다.

사용량은 화면에 표시하는 값이지 앱이 도는 데 필요한 값이 아니다. 조건에 들어갈 이유가 없었다.

### connectivity_plus는 인터페이스 연결만 본다

여기가 핵심이었다. 패키지 이름만 보면 인터넷 연결을 확인해주는 것처럼 읽히는데, 실제로 보장하는 범위는 네트워크 인터페이스가 붙어 있는지까지다.

```dart
final result = await Connectivity().checkConnectivity();
// ConnectivityResult.wifi  ← 연결됨으로 나온다
```

비행기 모드에서 와이파이만 따로 켜두면 인터페이스는 연결 상태다. 라우터에는 붙어 있으니까. 그런데 인터넷은 안 된다. 앱은 연결됐다고 판단하고 요청을 보내고, 그 요청은 실패한다.

### 오프라인 전환은 있는데 복구가 없었다

네트워크 실패 시 전역 상태를 오프라인으로 바꾸는 처리는 있었다. 그런데 다시 온라인으로 되돌리는 경로가 연결이 안 돼 있었다. 한 방향으로만 갔다.

### 다시 시도 버튼이 연결 확인을 안 했다

다시 시도가 원래 하려던 기능만 다시 불렀다. 오프라인 판정은 그대로 남아 있으니 또 막힌다. 몇 번을 눌러도 같은 화면이었다.

## 해결

### 1. 시작 조건에서 원격 조회를 뺐다

AI 사용량 조회는 표시 용도로만 쓰고, 앱 시작 조건에서 제외했다.

### 2. 연결 판정 기준을 바꿨다

- `connectivity_plus`가 미연결이라고 할 때만 그대로 믿는다
- 그 외에는 실제 API 요청이 실패했을 때 오프라인으로 판정한다

인터페이스가 없다는 건 확실한 정보고, 있다는 건 아니다. 그래서 확실한 쪽만 믿기로 했다.

### 3. 다시 시도를 두 단계로 만들었다

```
다시 시도 버튼
  → 인터넷 연결 확인 (실제 요청)
  → 성공하면 온라인 상태로 복구
  → 원래 실행하려던 동작을 콜백으로 받아 재실행
```

원래 동작을 콜백으로 넘기는 게 포인트다. 버튼이 뭘 다시 할지 알 필요가 없어진다.

## 결과

- 비행기 모드에서도 앱이 열리고 로컬 데이터로 할 일 관리가 된다
- 네트워크가 돌아오면 다시 시도 한 번으로 정상 상태가 된다
- AI 기능만 오프라인에서 막히고 그 사유가 화면에 구분돼서 뜬다

## 마치며

패키지가 알려주는 것과 내가 알고 싶은 것이 달랐다. 앞으로는 연결 상태를 쓰는 코드를 볼 때 이 패키지가 무엇까지 보장하는지 먼저 확인하려고 한다.

되돌리는 경로를 안 만든 것도 같은 성격의 실수였다. 오프라인으로 바꾸는 코드를 쓸 때 온라인으로 돌아오는 코드도 같이 있어야 했는데, 전환만 만들고 끝냈다.
