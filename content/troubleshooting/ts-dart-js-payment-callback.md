# 결제 결과가 JavaScript 콜백으로 들어온다

올해 초 웹 프로젝트에서 PG를 붙이면서 한 작업이다. 내가 제어할 수 없는 외부 모듈과 주고받는 구조를 다룬 게 이때가 처음이었다.

## 환경

- Flutter Web
- 외부 PG 스크립트 (결제창을 JS로 띄우는 방식)
- `dart:js_interop` / `@JS`

## 문제 상황

결제창은 외부 스크립트가 띄우고, 결과는 콜백으로 돌아온다. 여기서 세 개가 겹쳤다.

1. 결제 성공, 실패, 취소, 창 닫힘이 전부 같은 콜백으로 들어온다
2. 팝업이 차단되거나 스크립트가 로드되지 않으면 아무 응답도 안 온다. 화면은 계속 로딩
3. 같은 콜백이 여러 번 도착할 수 있다

3번은 잔액이 두 번 갱신되는 걸 보고 확인했다.

## 원인

### 타입 체계가 다르다

Dart와 JavaScript는 객체를 그대로 주고받을 수 없다. JS 객체를 Dart에서 받아 속성에 접근하려고 하면, 구조가 조금만 달라져도 런타임에서 깨진다. 결제 모듈 응답은 상황마다 필드가 다르게 온다.

### 호출 실패와 결과 실패가 구분이 안 됐다

결제창을 못 띄운 경우(스크립트 미로드, 팝업 차단)와, 창은 떴는데 결과가 실패인 경우(카드 거절, 사용자 취소)가 있다. 둘 다 "결제 안 됨"으로 뭉쳐 있었다. 사용자에게 보여줄 문구가 달라야 하는데 구분할 방법이 없었다.

### 중복 처리를 막는 게 없었다

콜백이 두 번 오면 잔액 재조회와 상태 갱신이 두 번 돌았다.

## 해결

### 1. 경계를 JSON 문자열로 고정했다

Dart와 JS 사이에는 문자열만 오간다. 객체를 안 넘긴다.

```dart
@JS('paypleOpen')
external void paypleOpen(String requestJson);

@JS('paypleRegisterCallback')
external void paypleRegisterCallback(JSFunction cb);

@JS('paypleIsLoaded')
external bool paypleIsLoaded();
```

받는 쪽에서 빈 응답과 파싱 실패를 따로 처리한다. 이렇게 하니 JS 쪽 구조가 바뀌어도 Dart는 파싱 단계에서만 깨진다.

### 2. 결과 판정은 응답 값 하나로

JSON 안의 결과 코드(`PCD_PAY_RST`)로 성공과 실패를 가른다. 예외 던지기와 섞지 않았다.

### 3. 첫 결과만 처리한다

```dart
var completed = false;

void onCallback(String json) {
  if (completed) return;   // 두 번째부터 버린다
  completed = true;
  // ... 결과 처리
}
```

지역 변수 하나면 됐다. 결제창 띄울 때 `false`로 두고, 첫 콜백에서 `true`로 바꾼 뒤 나머지는 무시한다.

### 4. 호출 자체의 실패를 따로 잡는다

결제창을 열기 전에 스크립트 로드 여부를 확인한다. 로드가 안 됐거나 호출이 실패하면 별도 예외로 던져서, 결제 결과 실패와 다른 문구를 보여준다.

### 5. 응답이 안 오는 경우를 대비한다

2분 타임아웃을 두고 대기를 끝낸다. 그다음엔 서버 기준으로 결제 상태를 확인한다. 클라이언트가 받은 콜백 말고 서버가 아는 사실을 믿는다.

### 6. 끝나면 서버와 맞춘다

결제와 환불 이후에 거래내역과 잔액을 서버에서 다시 조회해서 화면을 맞춘다. 콜백으로 받은 값으로 화면을 갱신하지 않는다.

## 결과

- 팝업이 차단돼도 화면이 대기 상태에 머물지 않는다
- 결제창을 못 연 경우와 결제가 실패한 경우에 다른 안내가 나간다
- 콜백이 여러 번 와도 처리는 한 번만 돈다
- 화면에 보이는 잔액이 항상 서버 값과 같다

## 마치며

내가 제어할 수 없는 쪽과 통신할 때는 세 가지를 먼저 정해야 했다. 결과가 언제 오는지, 몇 번 오는지, 안 올 수도 있는지.

특히 세 번째를 정해두지 않으면 화면이 계속 대기 상태로 남는다. 타임아웃은 뒤늦게 추가했는데, 설계 단계에 있었어야 할 항목이다.
