# 로그인에 실패했는데 세션 만료로 처리됐다

올해 초 웹 프로젝트에서 만난 버그다. 최근에 에러코드 체계를 다시 정리하다가 그때 생각이 나서 남긴다.

## 환경

- Flutter Web
- Dio
- 서버가 HTTP 상태 코드 안에 서비스 에러 코드를 담아 보내는 구조

## 문제 상황

로그인 화면에서 비밀번호를 틀렸다. 그랬더니 저장소가 비워지고 메인 화면으로 튕긴다.

로그인을 한 적도 없는 사용자에게 "세션이 만료되었습니다"가 뜨는 셈이다.

## 원인

### 상태 코드만으로는 성공을 알 수 없는 규격이었다

일부 API가 HTTP 200으로 응답하면서 본문에 오류 코드를 담아 보냈다.

```json
{ "code": 122, "message": "..." }
```

상태 코드만 보면 성공이다. 그래서 Dio를 이렇게 뒀다.

```dart
validateStatus: (_) => true,   // 상태 코드로 던지지 않는다
```

판단은 전부 본문 코드로 한다. 여기까지는 규격에 맞춘 것이라 문제가 없었다.

### 만료 코드를 모든 경로에 걸었다

백엔드와 "만료 판정은 서비스 에러 코드로 하자"고 정했다. 그래서 모든 API 경로에서 만료 코드를 검사하게 했다.

그런데 로그인 실패도 같은 코드로 내려왔다. 로그인은 아직 세션이 없는 상태다. 만료될 게 없다. 그런데 코드가 같으니 만료 처리가 그대로 돌았다.

저장소가 지워지고, 인증 상태가 미인증으로 바뀌고, 라우터가 메인으로 보냈다.

### 동시 요청이면 만료 처리가 여러 번 돌았다

화면에서 API를 두세 개 같이 부르는데 전부 만료를 감지하면, 만료 처리도 그 횟수만큼 실행됐다.

## 해결

### 1. 만료 판정을 인터셉터 한 곳으로 모았다

화면마다 흩어져 있던 검사를 걷어내고 통신 계층에서만 판정하게 했다. `onResponse`와 `onError` 양쪽에서 본문 코드를 본다.

```dart
const _tokenExpiredCodes = {122, 125};
```

### 2. 인증 경로를 만료 판정에서 뺐다

```dart
bool _isAuthExcluded(String path) =>
    path.contains('/auth') ||
    path.contains('/sign-in') ||
    path.contains('/sign-up');
```

아직 로그인 안 한 요청은 만료될 수가 없다. 그러니 판정 대상이 아니다. 같은 코드가 와도 로그인 경로에서는 입력 오류로 해석한다.

코드 값이 같아도 어느 경로에서 왔는지에 따라 뜻이 다르다는 걸 여기서 알았다.

### 3. 처리 중 플래그로 한 번만 돌게 했다

```dart
bool _handlingExpire = false;

Future<void> onTokenExpired() async {
  if (_handlingExpire) return;
  _handlingExpire = true;
  await clearStorage();   // 저장소를 먼저 비운다
  resetState();
}
```

저장소를 먼저 비우고 상태를 리셋하는 순서도 중요했다. 반대로 하면 상태가 바뀌어 라우터가 이동하는 동안 저장소에 값이 남아서, 복원 로직이 그걸 다시 읽어간다.

## 결과

- 로그인 실패는 입력 오류로, 세션 만료는 만료로 각각 안내된다
- 동시 요청 몇 개가 만료를 감지해도 처리는 한 번만 돈다
- 화면 쪽에는 만료 관련 코드가 남아 있지 않다

## 마치며

백엔드와 코드 체계를 정할 때 값만 정하고 맥락은 정하지 않은 게 원인이었다. 같은 122라도 로그인 요청에서 온 것과 데이터 조회에서 온 것은 다른 뜻이다.

전역 처리를 한 곳에 모으는 건 맞았다. 다만 모을 때 예외로 빠질 경로도 같이 정했어야 했다.
