# Flutter Web에서 새로고침하면 로그인이 풀린다

올해 초 웹 프로젝트에서 겪은 문제다. 최근에 앱 쪽에서 비슷한 상태 복원 문제를 또 만나면서 정리해두게 됐다.

## 환경

- Flutter Web
- Riverpod
- go_router
- Dio

## 문제 상황

로그인하고 아무 화면에서나 F5를 누르면 로그아웃된다. 메인으로 튕긴다.

그리고 튕기기 직전에 로그인 화면이 한 번 깜빡였다.

## 원인

### 웹의 새로고침은 앱 재시작이다

모바일 앱은 백그라운드에 갔다 돌아와도 메모리가 살아 있다. 웹은 다르다. 새로고침하면 처음부터 다시 빌드되고, Riverpod에 들고 있던 로그인 상태는 그대로 없어진다.

### 저장소를 모바일 앱 방식으로 골랐다

처음엔 로컬 저장소 하나에 사용자 정보를 전부 넣으려고 했다. 모바일에서 하던 방식이다. 웹은 조건이 다르다.

- 새로고침마다 앱이 재시작된다
- 인증 토큰은 요청마다 실려야 한다
- 공용 PC에서 정보가 남으면 안 된다

하나에 담을 성격이 아니었다.

### 복원은 하고 있었는데, 늦었다

깜빡임의 원인이 이거였다. 순서가 이랬다.

```
앱 재시작 → 상태 초기화 → 화면 렌더링
  → 라우터가 인증 확인 → 미인증 → 메인으로 이동
  → 뒤늦게 저장소에서 복원 → 이미 메인에 있음
```

복원 코드는 멀쩡히 있었다. 라우터가 인증을 확인하는 시점보다 늦게 돌았을 뿐이다.

## 해결

### 1. 저장 대상을 성격에 따라 나눴다

| 저장할 것 | 어디에 | 왜 |
| --- | --- | --- |
| 인증 토큰 | 쿠키 | 만료와 전송 범위를 제어할 수 있다 |
| 화면에 쓸 사용자 정보 | 세션 스토리지 | 탭 닫으면 사라진다 |

### 2. runApp 전에 읽어서 초기값으로 넣었다

```dart
void main() async {
  WidgetsFlutterBinding.ensureInitialized();

  // 첫 화면 그리기 전에 읽는다
  final saved = SessionStorage.get('user_info');
  final initial = saved != null ? User.fromJson(jsonDecode(saved)) : null;

  runApp(
    ProviderScope(
      overrides: [
        if (initial != null)
          userViewModelProvider.overrideWith(() => UserViewModel(initial)),
      ],
      child: const App(),
    ),
  );
}
```

순서가 이렇게 바뀐다.

```
앱 재시작 → 저장소 읽기 → 상태 초기값으로 주입
  → 화면 렌더링 → 라우터가 인증 확인 → 이미 로그인 → 원래 화면 유지
```

### 3. 저장과 삭제를 한 군데로 모았다

화면에서 브라우저 API를 직접 부르지 않게 래퍼를 뒀다. 로그아웃이나 토큰 만료 때 지울 걸 빠뜨리는 일이 없어진다.

## 같은 저장소 설계에서 한 번 더 걸렸다

한참 뒤에 결제 기능을 붙이고 나서 나온 버그다.

- 로그인하고 바로 결제 → 정상
- 새로고침하고 결제 → 구매자 정보가 빈 채로 전달됨

세션에는 화면에 보여줄 값만 저장하고 있었다. 닉네임, 코인. 이메일은 로그인 응답으로 받아서 메모리에만 뒀다. 새로고침하면 당연히 없다.

저장 범위를 "화면에 보이는 값" 기준으로 정한 게 문제였다. 새로고침 후에 필요한 값을 기준으로 잡았어야 했다. 세션 모델에 이메일을 넣고, 결제 요청 전에 필수 값이 비었는지 확인하는 처리를 추가했다.

## 결과

- 새로고침해도 로그인이 유지되고 보던 화면에 남는다
- 로그인 화면 깜빡임이 없어졌다
- 불필요한 재인증 요청이 사라졌다

## 마치며

무엇을 어디에 저장할지보다 언제 복원할지를 먼저 정했어야 했다. 빌드 전에 읽느냐 후에 읽느냐로 결과가 갈렸다.

저장 범위를 정하는 기준도 바뀌었다. 처음에는 화면에 뭘 보여줄지로 정했는데, 복원한 다음에 뭐가 필요한지로 정하는 게 맞았다.
