# 에러 156개 중 27개는 일부러 수집하지 않기로 했다

출시 전에 Crashlytics와 Analytics를 붙였다. 기본 설정만 해도 크래시는 올라간다. 고민한 건 직접 정의한 에러를 어디까지 보낼 거냐였다.

## 전부 모으면 아무것도 안 보인다

앱에 정의된 에러가 156개였다. 처음엔 다 보내려고 했다. 많이 모을수록 좋다고 봤다.

며칠 굴려보니 아니었다. 사용자가 입력을 잘못했을 때 뜨는 것까지 전부 올라오니까, 정말 고쳐야 할 게 그 안에 묻혔다. 대시보드 맨 위에 "제목을 입력해주세요"가 있으면 볼 이유가 없다.

## 기준을 하나로 잡았다

내가 고쳐야 하는 것만 보낸다.

이 기준으로 나누니 정리가 됐다.

| 보낸다 | 안 보낸다 |
| --- | --- |
| 저장 실패, 동기화 실패 | 필수 입력 누락 |
| 서버 응답 이상, 파싱 실패 | 사용자가 취소함 |
| 예상 못 한 상태 전이 | 권한 거부 (사용자 선택) |
| 초기화 실패 | 입력 형식 오류 |

수집 129개, 제외 27개가 됐다. 제외한 27개는 전부 사용자가 그렇게 행동한 결과지 버그가 아니다.

## Analytics는 더 좁게

이벤트는 더 줄였다. 처음엔 화면 진입마다 다 찍으려다 멈췄다.

나중에 볼 이유가 분명한 것만 남겼다. 핵심 지표 네 개다. 나머지는 필요해지면 그때 추가하면 된다. 반대로 한 번 붙인 이벤트는 잘 못 뗀다. 지표가 끊기는 게 싫어서다. 그래서 적게 시작했다.

## 수집이 안 닿는 곳

붙여놓고 보니 로그가 안 잡히는 구간이 있었다. 네 군데다.

**라우터 바깥.** 전역 에러 화면처럼 라우터가 관리하지 않는 화면은 화면 식별자가 안 붙는다. 어디서 난 건지 모른 채 에러만 올라온다.

**초기화 순서.** Crashlytics가 초기화되기 전에 난 에러는 당연히 안 올라간다. 앱 시작 구간이 제일 위험한데 하필 거기가 사각지대다. 초기화를 최대한 앞으로 당기는 것 말고는 방법이 마땅치 않았다.

**바텀시트.** 화면 위에 올라오는 시트는 라우터 기준으로 아래 화면에 있는 걸로 잡힌다. 사용자가 보고 있는 건 시트인데 기록은 다른 화면으로 남는다.

**화면 식별자 불일치.** 문서에 정의한 화면 ID와 코드에서 쓰는 값이 어긋난 곳이 있었다. 수집은 되는데 대조가 안 된다.

## 마치며

관측 도구를 붙이는 일은 모으는 설정보다 거르는 설계에 가깝다. 뭘 안 볼지 정하지 않으면 봐야 할 게 안 보인다.

그리고 붙인 다음에는 안 잡히는 곳을 먼저 찾아야 한다. 대시보드에 없는 에러가 안 난 에러는 아니다.
