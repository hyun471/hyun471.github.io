# 반응형 기준을 물리 픽셀로 잡으면 안 되는 이유

Android는 화면 크기가 제각각이다. 여기에 폴더블이 끼면 같은 기기 안에서도 폭이 바뀐다. 접었을 때와 펼쳤을 때 레이아웃이 달라야 한다.

iOS도 폴더블 출시가 예고되면서 더 미룰 수 없게 됐다.

## 물리 픽셀과 논리 픽셀

먼저 정리해야 할 게 있었다.

- 물리 픽셀은 화면에 실제로 박힌 점의 개수
- 논리 픽셀은 OS가 앱에 알려주는 좌표 단위. Flutter의 `MediaQuery.size`가 주는 값

둘의 비율이 devicePixelRatio다. 고해상도 기기는 이 값이 3~4까지 간다.

그래서 물리 픽셀 1080px인 화면이 논리 픽셀로는 360일 수 있다. 물리 픽셀로 기준을 잡으면 손바닥만 한 폰과 태블릿이 같은 구간에 들어간다.

기준은 논리 픽셀이어야 한다. 사람 눈에 보이는 크기에 비례하는 쪽이 그쪽이다.

## 세 구간으로 나눴다

```dart
if (width < 600) return phone;
if (width < 840) return foldable;
return tablet;
```

| 구간 | 논리 폭 | 대상 |
| --- | --- | --- |
| phone | < 600 | 일반 폰, 폴더블 접은 상태 |
| foldable | 600 ~ 839 | 폴더블 펼친 상태, 작은 태블릿 |
| tablet | ≥ 840 | 태블릿 |

600과 840은 Material Design의 윈도우 크기 구간과 같은 값이다. 직접 정해볼까 하다가 그만뒀다. 이미 검증된 기준을 쓰는 게 낫다고 봤다.

## 나눈 다음이 더 어려웠다

구간 나누는 건 시작이었다.

### 폴더블 펼친 화면과 태블릿을 같은 디자인으로 보이게 하기

논리 픽셀 기준으로 크기를 조정해서 두 화면의 구성이 같아 보이도록 맞췄다. 폭이 다른데 디자인이 완전히 달라지면 같은 앱처럼 안 보인다.

### 구조가 다르면 라우팅도 다르다

세로 폰은 화면을 하나씩 쌓아 올리고, 와이드에서는 목록과 상세를 한 화면에 둔다. 그러면 같은 경로인데 보여줄 화면 구성이 다르다. 위젯만 갈아 끼워서는 해결이 안 되고 라우트를 어떻게 쌓을지부터 다시 봐야 했다. 결국 한 번 정리하고 넘어갔다.

### 상태와 기능은 공유해야 한다

레이아웃은 나누되 동작은 하나여야 한다. 폰용과 와이드용을 따로 만들면 기능 하나 고칠 때마다 두 군데를 고치게 된다.

## 마치며

반응형에서 정할 첫 번째는 브레이크포인트 숫자가 아니라 뭘 기준으로 잴 거냐였다. 물리 픽셀은 화면의 사정이고 논리 픽셀이 사용자가 보는 크기다.

그리고 폭이 바뀌면 위젯만 바뀌는 게 아니었다. 화면 구성이 바뀌면 경로도 따라 바뀐다.
