# Flutter Web은 검색 크롤러에게 빈 페이지다

올해 초 웹 프로젝트에서 있었던 일이다. 기술 문제라기보다 판단 문제에 가까운데, 그래서 더 남겨두고 싶었다.

## 계획

서비스에 수익 모델을 붙여야 했다. 이렇게 잡았다.

1. 가입하면 기본 코인을 준다
2. 코인을 다 쓰면 리워드 광고를 보고 코인을 받는다

광고를 붙이려면 AdSense 승인이 필요하다. 심사에 넣었고, 콘텐츠가 부족하다는 사유로 반려됐다.

## 왜 콘텐츠가 없다고 나왔나

서비스에 소개도 있고 이용 안내도 있었다. 사람이 들어가면 다 보인다.

문제는 그게 전부 Flutter 안에 있었다는 것이다.

Flutter Web은 화면을 캔버스에 그린다. HTML 요소로 텍스트가 쌓이는 게 아니라 그림이 그려진다. 크롤러가 페이지를 받으면 이런 걸 본다.

```html
<body>
  <script src="main.dart.js"></script>
  <!-- 텍스트 없음 -->
</body>
```

읽을 게 없다. 사람에게는 꽉 찬 페이지고 크롤러에게는 빈 페이지였다.

SPA 전반의 문제이긴 한데, Flutter Web은 DOM에 텍스트를 아예 안 남기는 방식이라 더 심하다.

## 1차 대응: 정적 HTML을 만들었다

읽을 게 없으면 만들어주면 된다고 생각했다. Flutter 바깥에 정적 페이지를 따로 만들었다.

- 서비스 소개
- 이용 가이드
- 개인정보처리방침
- 오픈소스 고지

여기서 딸린 문제가 하나 더 나왔다. 이 페이지들은 Flutter 렌더링 영역 밖이라, 앱에서 언어를 바꿔도 같이 안 바뀐다. 그건 따로 해결해야 했다.

재심사를 넣었다. 또 반려됐다.

## 판단: 승인에 일정을 묶을 수 없었다

여기서 선택지가 둘이었다.

1. 콘텐츠를 더 늘려서 재심사를 계속 넣는다
2. 수익 모델을 바꾼다

1번의 문제는 언제 끝날지 모른다는 것이었다. 무엇이 얼마나 부족한지 구체적으로 알려주지 않는다. 그동안 서비스는 멈춰 있어야 한다. 코인을 얻을 방법이 없으니 무료 코인을 다 쓴 사용자는 더 쓸 수가 없었다.

승인 날 때까지 기다린다는 건 외부 심사에 일정을 맡긴다는 뜻이었다. 그래서 결제 연동으로 바꿨다. 광고를 보고 코인을 받는 대신 코인을 구매하는 경로로.

정적 페이지 작업이 버려진 건 아니다. 개인정보처리방침과 오픈소스 고지는 어차피 있어야 했고, 결제를 붙이려니 이용약관과 환불 정책이 더 필요했다.

## 마치며

Flutter Web을 고를 때 검색에 안 잡힌다는 걸 계산에 넣지 않았다. 사내 도구나 로그인 뒤의 서비스라면 상관없는데, 외부 유입이나 광고가 수익 모델에 들어가면 전제가 무너진다. 기술 선택은 화면을 어떻게 그리느냐만 정하는 게 아니라 그 바깥까지 정한다.

외부 심사에 막혔을 때 기다릴지 돌아갈지도 정해야 했다. 계속 붙잡는 것도 선택이지만, 뭘 포기할지 정하는 것도 개발의 일부였다.
